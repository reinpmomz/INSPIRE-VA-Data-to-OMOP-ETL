# INSPIRE-VA-Data-to-OMOP-ETL
This repository contains code to ETL Verbal Autopsy data from various HDSS sites in Africa to an OMOP database instance

## Requirements

### Hardware
A laptop/desktop with the following specifications is recommended:

- **Processor:** Intel Core i5 or higher (higher core count is beneficial for parallel processing)
- **RAM:** 16GB (recommended for most OHDSI workloads). If you anticipate running multiple containers or handling large datasets, consider upgrading to 32GB.
- **Storage:** Minimum 500GB, but more (1TB) is better with a Solid-State Drive (SSD)
- **Operating System:** Windows 10 version 2004 and higher (Build 19041 and higher) or Windows 11. This allows you to install the Windows Subsystem for Linux (WSL) and WSL 2 using a single, streamlined command.

### Software

- White rabbit
- Rabbit in a hat
- Athena
- Usagi
- DBMS(Postgres, MySQL, SQLite etc)
- Java 1.8 or higher. But preferably Java JDK
- R and Rtools

- **Data used for ETL:** Data for Six Health and Demographic Surveillance System (HDSS) Sites in folders `VA_Hararghe_HDSS - Ethiopia`, `VA_IgangaMayuge_HDSS - Uganda`, `VA_MEIRU_Karonga_HDSS - Malawi`, `VA_Niakhar_HDSS - Senegal`, `VA_NUHDSS - Kenya` and `VA_Ouagadougou_HDSS - Burkina Faso`

After permission is granted, download the data and save the six folders inside the [data](./data) folder. Each individual folder contains Stata DTA files **(Do not rename the folders and DTA files)**.

## ETL Steps Followed

1. **Data processing:** Cleaning and Exploratory data analysis.
2. **Data Profiling:** Generate Scan Report in White Rabbit using the CSV `VA_INSPIRE_merged_final.csv` generated in the data processing step and saved in the output folder. Before running the scan report, set the working directory to [3.scan_report](./3.scan_report) folder
3. Create a `SOURCE CODE LIST` from either the SCAN Report Generated or using your own generated descriptive output. See the [4.source_code_list](./4.source_code_list) folder.
4. **Vocabulary Mapping:** Source code lists are loaded into `USAGI` to map source codes into the OMOP Vocabulary (standard terminologies). Final mapping generated by USAGI can be exported into the OMOP Vocabulary’s `SOURCE_TO_CONCEPT_MAP` and `usagi_mapping_concept_list.csv` **(This file should not be edited as it can be loaded back into USAGI to make edits and changes on concepts)**. Details regarding the mapped concepts can be found in the [5.usagi_concept](./5.usagi_concept) folder.
5. **ETL Mapping:** Generate documentation for the ETL process using `Rabbit-In-a-Hat`. Rabbit-In-a-Hat reads and displays a White Rabbit scan report through a graphical user interface to allow a user to connect source data to tables and columns within the OMOP-CDM. ETL design and implementation process from source to OMOP CDM can be found in the [6.mapping](./6.mapping) folder.
6. **ETL Implementation:** R scripts in [7.etl_to_omop](./7.etl_to_omop) used for transforming source data to CDM using source codes to OMOP terminologies. 
7. **Data Quality Checks:** Install 'DataQualityDashboard' R package and run the script in [8.dqd](./8.dqd) against the OMOP database to generate the DQD Dashboard. Visit [OHDSI DQD GitHub](https://github.com/OHDSI/DataQualityDashboard) for more information on DQD documentation and installation.
8. **Data characterization:** Generate aggregated (Results tables) data using the script in [9.achilles_results](./9.achilles_results) against the OMOP database for Atlas using the 'Achilles' R package by OHDSI. Visit [OHDSI Achilles GitHub](https://github.com/OHDSI/Achilles) for more information on documentation and installation.
9. **OMOP Analysis:** Characterise and visualise an Observational Medical Outcomes Partnership (OMOP) Common Data Model (CDM) instance with 'OmopSketch' R package using using scripts in [10.omop_analysis](./10.omop_analysis)
10. **Visualization in Atlas:** Aggregated data(results tables), OMOP tables, and vocabulary tables were integrated with Atlas and webAPI. Visit [OHDSI GitHub](https://github.com/OHDSI/WebAPI/wiki/CDM-Configuration) for more information.

## Run ETL in R

After cloning the repository or downloading the ZIP, you also need the data files (**Data used for ETL**) in the [data](./data) folder.

Open `RStudio` then set your working directory to the _INSPIRE-VA-Data-to-OMOP-ETL_ folder. 

- To run individual files, open the `main.R` script, and run from the beginning.

- Copy the code below to run all files at once in Rstudio

```
source("main.R")

```
