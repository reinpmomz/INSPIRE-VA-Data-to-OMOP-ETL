# INSPIRE-VA-Data-to-OMOP-ETL
This repository contains code to ETL Verbal Autopsy data from various HDSS sites in Africa to an OMOP database instance

## Requirements

### Hardware
A laptop/desktop with the following specifications is recommended:

- **Processor:** Intel Core i5 or higher (higher core count is beneficial for parallel processing)
- **RAM:** 16GB (recommended for most OHDSI workloads). If you anticipate running multiple containers or handling large datasets, consider upgrading to 32GB.
- **Storage:** Minimum 500GB, but more (1TB) is better with a Solid-State Drive (SSD)
- **Operating System:** Windows 10 version 2004 and higher (Build 19041 and higher) or Windows 11. This allows you to install the Windows Subsystem for Linux (WSL) and WSL 2 using a single, streamlined command.

### Software

Download and install

- [Java 1.8 or higher](https://www.java.com/en/). But preferably [Java JDK](https://www.oracle.com/africa/java/technologies/downloads/)
- [White rabbit and Rabbit in a hat](https://github.com/OHDSI/WhiteRabbit)
- Athena is a web-based resource tool for OMOP vocabulary. [Link to Register and access](https://athena.ohdsi.org/search-terms/start)
- [Usagi](https://github.com/OHDSI/Usagi)
- [DBMS(PostgreSQL)](https://www.postgresql.org/download/)
- [**R software**](https://www.r-project.org/), followed by [**Rtools**](https://cran.r-project.org/bin/windows/Rtools/) corresponding to your R version then [**RStudio/Posit IDE**](https://posit.co/download/rstudio-desktop/).

## ETL Steps Followed

1. **Data processing:** Cleaning and Exploratory data analysis.
2. **Data Profiling:** Generate a Scan Report in White Rabbit using the CSV `VA_INSPIRE_merged_final.csv` generated in the data processing step and saved in the output folder. Before running the scan report, set the working directory to the [3.scan_report](./3.scan_report) folder
3. Create a `SOURCE CODE LIST` from either the SCAN Report generated or using your own generated descriptive output. See the [4.source_code_list](./4.source_code_list) folder.
4. **Vocabulary Mapping:** Source code lists are loaded into `USAGI` to map source codes into the OMOP Vocabulary (standard terminologies). Final mapping generated by USAGI can be exported into the OMOP Vocabulary’s `SOURCE_TO_CONCEPT_MAP` and `usagi_mapping_concept_list.csv` **(This file should not be edited as it can be loaded back into USAGI to make edits and changes to concepts)**. Details regarding the mapped concepts can be found in the [5.usagi_concept](./5.usagi_concept) folder.
5. **ETL Mapping:** Generate documentation for the ETL process using `Rabbit-In-a-Hat`. Rabbit-In-a-Hat reads and displays a White Rabbit scan report through a graphical user interface to allow a user to connect source data to tables and columns within the OMOP-CDM. ETL design and implementation process from source to OMOP CDM can be found in the [6.mapping](./6.mapping) folder.
6. **ETL Implementation:** R scripts in [7.etl_to_omop](./7.etl_to_omop) are used for transforming source data to CDM using source codes to OMOP terminologies. 
7. **Data Quality Checks:** Install the `DataQualityDashboard` R package and run the script in [8.dqd](./8.dqd) against the OMOP database to generate the DQD Dashboard. Visit [OHDSI DQD GitHub](https://github.com/OHDSI/DataQualityDashboard) for more information on DQD documentation and installation.
8. **Data characterization:** Generate aggregated (Results tables) data using the script in [9.achilles_results](./9.achilles_results) against the OMOP database using the `Achilles` R package by OHDSI. Visit [OHDSI Achilles GitHub](https://github.com/OHDSI/Achilles) for more information on documentation and installation.
9. **Visualization in Atlas:** Aggregated data(results tables), OMOP tables, and vocabulary tables were integrated with `Atlas and webAPI`. The installation guide for Windows OS can be found in [10.atlas_analysis](./10.atlas_analysis). Visit [OHDSI GitHub](https://github.com/OHDSI/WebAPI/wiki/CDM-Configuration) for more information.
10. **OMOP Analysis:** Characterise and visualise an Observational Medical Outcomes Partnership (OMOP) Common Data Model (CDM) instance with the `OmopSketch` R package using scripts in [11.omop_analysis](./11.omop_analysis)
11. **OHDSI network study:** Characterize the OMOP-CDM instances and create a profile that results in a resource that allows a user to use the profile of a database to determine if that database has the elements necessary to answer clinical questions of interest. Install the `DbDiagnostics` and `OhdsiSharing` R packages and run the scripts in [12.evidence_network_study](./12.evidence_network_study)

## Run ETL in R

After cloning the repository or downloading the ZIP, you also need the data files (**Data used for ETL**) in the [data](./data) folder.

Open `RStudio`, then set your working directory to the _INSPIRE-VA-Data-to-OMOP-ETL_ folder. 

- To run individual files, open the `main.R` script and run from the beginning.

- Copy the code below to run all files at once in RStudio

```
source("main.R")

```
